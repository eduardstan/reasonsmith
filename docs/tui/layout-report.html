Decoration goes first

A terminal is a fixed grid that the reader resizes. This renderer carried no notion of the one it drew on — every width in it was a literal — so it was rebuilt around a single measurement, and around one rule for what to drop when the grid runs out.

The rule: decoration goes first, labels go second, and a claim never goes at all. A narrow terminal loses the ASCII masthead, then the ladder caption, then the words beside the counters. It keeps every verdict, every count, the undeclared-domain notice, and the audience, at any width the program will run in. That ordering is not taste. A layout that dropped a violated count to fit its own brand mark would be making a presentation decision about a compliance finding.

Found by running it

Six defects the source did not show

Every one of these was invisible in review and obvious on screen. They were caught by driving the real program under terminal-control and reading the grid it produced.

A one-row box has no room for its border

The status bar and the footer were bordered boxes one cell tall, so the frame took the row and the contents were drawn into the border line.

was│ 3 observe· 1 violate· 2 unattainabl─ladder:─┘
now 6 req │ 3 observed · 1 violated · 2 unattainable

Both bars lost the border. Four rows went back to the findings list.

Two panels drawn over each other

The detail route's back link claimed no height, so the scroll region below it drew over the same row, character by character.

was←cbacketobfindingsb_2_principal_reasons_complete
now← back to findings ecoa_reg_b_1002_9_b_2_principal_reasons_complete

Spacing that is not a character does not survive

Three arrangements failed before one held: sibling elements with a gap; a separator beside them, where gap does not apply between the children of a fragment; and a content prop, which is trimmed at each end.

wasctrl+pcommands enteropen qquit
nowctrl+p commands · enter open · q quit

A cap is measured, never guessed

The ladder caption had a fixed column threshold and the footer capped hints per breakpoint. Neither can know how wide its contents are — they grow with the pack — so the caption was drawn into the last counter and the hints pushed the audience off the end.

was2 unattainableladder: unattainable → probed →
now2 unattainable (caption hidden; it does not fit)

The masthead, twice

The findings route mounted a second header inside the panel the shell had already mounted one above — so the screen a reader lands on drew the brand mark, the tab row and the breadcrumb twice, costing four rows of findings to say the same thing again.

One breach, counted twice

The violated count had a chip of its own and an entry in the counter loop, so a run with one breach printed 1 violated twice, three cells apart. Beside it, a second + settings tab navigated where the Settings tab already did.

The thresholds

What each width costs

Only elements whose own width is fixed and known sit behind a breakpoint. Anything whose contents can grow measures itself against the terminal.

  • < 88The ASCII masthead becomes a one-line word mark. It is the only element in the header that tells a reader nothing about their run.
  • < 72The counters keep their numbers and lose their words. The findings list drops the classification column rather than clipping it to bindin / interpr — the same fact is on the detail screen in full.
  • < 64Panel gutters go to zero.
  • < 24 rowsVertical gaps collapse and the headline row goes — the status bar shows the same counts individually one row below.
  • neverA verdict, a count, the undeclared-domain notice, and the audience. The audience decides what every other panel withholds, and a reader who cannot see which projection they are in cannot tell a field that is absent from one that was suppressed.

Provenance

What produced these screens

The record behind every capture was produced by the real reasonsmith Python serialiser — ConformanceReport.to_dict() over the shipped ECOA pack, with the pack's own statutory text — and replayed to the TUI through its --python hook, so the renderer's argument building, subprocess spawn and JSON parse all ran unchanged. No screen here is a mock-up, and no verdict on one was decided by the TypeScript.
